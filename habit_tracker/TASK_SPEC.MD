# Спецификация: Habit Tracker

## 1. Цель

Создать небольшое клиентское приложение для ежедневного отслеживания привычек. Данные должны сохраняться в браузере и быть доступны после перезагрузки страницы.

Главный принцип проекта — не выходить за пределы описанного scope.

## 2. Пользовательские возможности

Пользователь может:

1. Создать привычку, указав только название.
2. Отметить привычку выполненной сегодня.
3. Снять отметку о выполнении повторным нажатием.
4. Увидеть количество выполнений.
5. Удалить привычку после подтверждения действия.
6. Перезагрузить страницу и не потерять привычки и данные о выполнениях.

Авторизация, backend, облачная синхронизация и календарь на год не входят в scope.

## 3. Правила создания привычки

- Название является единственным полем привычки.
- Название после нормализации не может быть пустым.
- Перед сохранением необходимо:
  - удалить пробелы в начале и конце названия;
  - заменить последовательность из двух и более пробельных символов между словами одним пробелом.
- Две привычки с одинаковым нормализованным названием создавать нельзя.
- При ошибке валидации привычка не создаётся, а пользователь получает понятное сообщение.

## 4. Отметка выполнения

- У каждой привычки есть состояние «выполнено сегодня».
- Отметка работает как переключатель: повторное действие снимает её.
- При наступлении нового локального дня отметка за предыдущий день не считается отметкой за сегодня и отображается как снятая.
- История предыдущих выполнений не удаляется при смене дня.
- Переключение отметки должно сохраняться в `localStorage`.

## 5. Количество выполнений и история

- В текущем ответе счётчик определён как количество привычек, отмеченных выполненными за текущий день.
- Данные о выполнениях за предыдущие дни должны сохраняться, поскольку общий счётчик/история не должны обнуляться при наступлении нового дня.
- Формат отображения исторических данных (дата создания привычки или история выполнений) пока требует уточнения; до уточнения не добавлять расширенный календарь или аналитику.

## 6. Удаление

- Перед удалением привычки необходимо запросить подтверждение.
- После подтверждения привычка и связанные с ней данные удаляются.
- Восстановление удалённой привычки не требуется.

## 7. Пустое состояние

Если привычек нет, приложение показывает пустое состояние с подсказкой, объясняющей, как создать первую привычку.

## 8. Хранение данных

- Для хранения используется только браузерный `localStorage`.
- После перезагрузки страницы приложение восстанавливает сохранённые привычки, их дату создания и данные о выполнениях.
- Минимальная структура привычки должна содержать:
  - уникальный идентификатор;
  - нормализованное название;
  - дату создания;
  - сохранённые даты выполнений.
- Конкретные правила обработки повреждённых данных, имя ключа `localStorage`, версионирование схемы и формат дат требуют уточнения.

## 10. Критерии готовности MVP

- Можно создать валидную привычку с названием.
- Пустое или дублирующееся название отклоняется.
- Лишние пробелы в названии нормализуются.
- Выполнение можно отметить и снять за текущий день.
- При смене дня отметка за сегодня сбрасывается, а сохранённые данные прошлых дней не теряются.
- На экране отображается согласованный счётчик выполнений.
- Удаление требует подтверждения.
- Пустое состояние отображается, когда список привычек пуст.
- После перезагрузки страницы данные восстанавливаются из `localStorage`.
- В приложение не добавляются авторизация, backend, облачная синхронизация и годовой календарь.
