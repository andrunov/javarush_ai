# Вопросы для обсуждения

Ниже перечислены вопросы, которые нужно уточнить до реализации Habit Tracker. Они помогают сохранить проект в рамках заданного scope.

## Функциональность

1. Как пользователь создаёт привычку: достаточно одного обязательного поля «Название», или нужны дополнительные свойства (описание, цвет, иконка)? - Только название
2. Нужно ли запрещать создание привычки с пустым названием и/или автоматически обрезать пробелы по краям? - Название с пустым названием запретить, а пробелы по краям обрезать. Так же обрезать лишние пробелы между словами (если есть такие, больше одного пробела)
3. Допускаются ли две привычки с одинаковым названием? - нет
4. Отметка «выполнено сегодня» должна быть переключателем: повторный клик снимает отметку или отметку можно только поставить? - снимает
5. Должна ли отметка за сегодня автоматически сбрасываться при наступлении нового дня, сохраняя при этом общий счётчик выполнений? - да, именно так. Отметка сбрасывается, общий счетчик остается
6. Что именно означает «количество выполнений»: количество всех отмеченных дней за всё время или количество последовательных дней (streak)? - количество всех отмеченных привычек за текущий день
7. Нужно ли показывать дату создания привычки или историю выполнений, либо достаточно текущего статуса и общего количества? - нужна дата создания привычки или историю выполнений
8. Нужно ли подтверждение перед удалением привычки? Восстановление после удаления не требуется? - Нужно подтверждение. Восстановление не требуется
9. Что отображать, если привычек ещё нет: короткое сообщение, пустое состояние с подсказкой или сразу форму создания? - пустое состояние с подсказкой

## Хранение данных

10. Какой формат даты использовать для определения «сегодня» — локальную дату устройства пользователя или UTC?
11. Достаточно ли хранить для каждой привычки название, список дат выполнения и идентификатор, или нужен другой минимальный формат данных?
12. Как приложение должно вести себя при повреждённых или неподдерживаемых данных в `localStorage`: очистить их, проигнорировать проблемные записи или показать ошибку?
13. Нужно ли предусмотреть версию схемы данных для будущих изменений, или для учебной задачи достаточно одной текущей схемы?
14. Какое имя ключа `localStorage` использовать? Должны ли данные разных приложений/окружений быть полностью изолированы?

## Интерфейс и ограничения

15. Есть ли предпочтения по визуальному стилю, цветам, языку интерфейса и текстам сообщений? По умолчанию использовать русский язык и простой адаптивный интерфейс?
16. На каких минимальных размерах экрана интерфейс должен оставаться удобным (мобильный экран обязателен)?
17. Нужны ли состояния загрузки, ошибки записи в `localStorage` и уведомление об успешном создании/удалении?
18. Нужны ли требования к доступности: управление с клавиатуры, видимые focus-состояния и корректные подписи элементов формы?

## Технические решения

19. На каком стеке и с помощью какого шаблона нужно реализовать приложение (например, чистые HTML/CSS/JavaScript или уже выбранный фреймворк)?
20. Нужно ли написать автоматические тесты для создания, отметки, удаления и восстановления данных после перезагрузки?
21. Какие браузеры необходимо поддерживать?
22. Должно ли приложение работать только в одном окне/вкладке, или изменения в другой вкладке должны синхронизироваться через событие `storage`?
